## Uploaded BimmerLabs NoMAF tune

Package: `MSV70_S7623406_330i_NoMAF.zip`

Primary file header:

- Generated by BimmerLabs
- Generator version: 0.8.76
- Date: 2018-03-16 18:44:17
- Author: hassmaschine
- `$REFERENZ 0049PP0L921S0AC3S 4`

This matters: the project-car read is **AC1S**, while the BimmerLabs tune is **AC3S**. A direct byte/XDF diff therefore combines:

1. BMW's AC1S -> AC3S software/calibration revision, and
2. BimmerLabs NoMAF/performance-tune changes.

Do **not** label all direct differences as NoMAF changes.

MS4X Firmware Finder identifies the AC3S US E90 N52B30OL RWD entry as ZUSB `7623405`, SW `7623406`, HW `7577968`, reference `L921S0AC3S`.

### High-confidence MAFless indicators

Using the native 9PPL921S XDF, the uploaded NoMAF file differs from the AC1S project-car read in several parameters whose semantics directly involve the MAF/fallback airflow path:

| Parameter | AC1S | BimmerLabs AC3S NoMAF | XDF description |
|---|---:|---:|---|
| `c_conf_maf` | 2 | 1 | Configuration of mass air flow meter learning |
| `c_abc_inc_maf` | 2 | 0 | Debounce counter increment, mass air flow meter diagnosis |
| `fmy_id_maf.dtc` | 259 | 0 | MAF diagnostic DTC declaration |
| `fmy_id_maf.c_err_clas` | 86 | 0 | MAF failure class |
| `c_abc_inc_load_tps_plaus` | 2 | 0 | Load/throttle plausibility debounce increment |
| `fmy_id_load_tps_plaus.dtc` | 5156 | 0 | Load/throttle plausibility DTC declaration |
| `fmy_id_load_tps_plaus.c_err_clas` | 86 | 0 | Load/throttle plausibility failure class |

`ip_maf_1_diag__n__tps_av`, described by the XDF as **Substitute mass air flow through MTC**, is also changed.

These are strong clues about how the BimmerLabs tune intentionally places MSV70 on a modeled/substitute-airflow path.

### It is not a pure MAF-delete patch

The direct comparison contains 2,881 differing calibration bytes. 2,592 of those occur in storage covered by the native XDF. There are 84 changed XDF components across 82 unique calibration titles.

The tune also changes full-load lambda, torque-model tables, requested torque, throttle targets, Valvetronic lift, exhaust/air-model tables, and other performance calibrations.

This matches hassmaschine's public description of the BimmerLabs NoMAF file as a **full tune** based on his own 330i calibration, not merely a MAF-off switch.

### Full-load lambda

`ip_lamb_fl__n` in the project-car AC1S calibration:

- 5504 rpm: lambda ~0.9008
- 6496 rpm: lambda ~0.8705

The BimmerLabs NoMAF file is effectively flat at lambda ~0.9203 through a final 7200-rpm breakpoint. At gasoline stoich 14.7:1, lambda 0.9203 is approximately 13.53:1 AFR.

This also agrees with hassmaschine's public explanation that the tune flattened the 330i WOT curve around 13.5:1 and reduced the stock high-rpm catalyst-protection enrichment.

### Other notable direct differences

These are useful as tuning inspiration but are **not yet isolated from the AC1S -> AC3S revision confound**:

- `KL_MDMAX`: upper portion raised toward 300 Nm.
- `KF_MDIOP_1` / `KF_MDIOP_2`: high-load torque-model cells increased roughly 10% in the directly differing regions.
- `KL_LAMX` / `KL_LAMX_FV`: high-rpm load breakpoints/limits extended slightly.
- `KL_HUBEVL`: full-load valve lift reaches 10.0 mm vs 9.7 mm in AC1S.
- `KL_HUBV`: 10.0 mm vs 9.7 mm.
- `KF_WDKDPS`: substantial throttle-target changes.
- Full-load lambda breakpoint extended to 7200 rpm.

For turbo development, the useful abstraction is **model-based airflow + torque + throttle/Valvetronic coordination**. Blindly copying the performance changes would be a bad base tune.

## RSA-delete package

Package: `MSV70_RSADelete_0049PP0L921S.zip`

Primary file header:

- Generated by BimmerLabs
- Version 0.8.53
- Date: 2017-12-30 18:58:55
- Author: hassmaschine
- `$REFERENZ 0049PP0L921S F`

The included README explicitly describes this as a boot/program-space security patch rather than a normal calibration tune.

The uploaded BMW stock `7577968A.0pa` and RSA-delete `.0pa` overlap on 1,602,576 Intel-HEX addresses. Only 29 bytes differ in that common address set. The RSA file also explicitly carries about 100k addresses that are omitted from the sparse stock `.0pa`, so "29 bytes" should not be interpreted as the entire RSA package size or as proof that only 29 physical flash bytes are involved.

Keep RSA/program-space work completely separate from calibration experiments.

## Revision-matched comparison complete

The stock AC3S / `S7623406.0da` calibration is now hash-anchored and has been
compared directly with the BimmerLabs AC3S NoMAF file:

```
BimmerLabs NoMAF AC3S - stock AC3S
```

Across the 125,424 parameter bytes explicitly present in both files, the
revision-matched tune changes 2,750 bytes, 80 XDF components, and 78 unique
XDF titles. This is the authoritative NoMAF/performance-tune comparison; the
earlier AC1S-to-AC3S 84-component/82-title comparison above remains historical
and revision-confounded. Detailed rows are in
`stock_ac3s_vs_bimmerlabs_nomaf_ac3s_xdf_changes.csv` (supporting artifact withheld from public edition).

Separately, the cleaner way to identify BMW's actual NoMAF strategy remains the intersection of the two matched factory comparisons already identified in MS4X:

```
E91 LHD RWD EU4: NoMAF - MAF
                 INTERSECT
E90 LHD AWD EU4: NoMAF - MAF
```

That avoids confusing hassmaschine's performance tune with BMW's underlying MAFless model.
